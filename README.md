# babyshower.com.py

Marketing site for babyshower.com.py, a Paraguayan baby shower, first-birthday and kids-party
decoration service. It is a WhatsApp-first brochure site: package and price pages, theme and zone
pages, guides, a price calculator, and one enquiry form handled by a small PHP endpoint. The
site copy is Spanish (es-PY, voseo). There is no database and no online booking.

## Stack

- Static HTML generated by Node 22 (`build-site.mjs`, no npm dependencies, no `node_modules`).
- One PHP 8.1+ endpoint, `lead-forward.php`, for the enquiry form (mail, optional CRM).
- Hostinger Git deploy of `master`: the server clones the repo as-is and runs no build.

## Generated output is committed

The built HTML is checked in because Hostinger does not build. Never hand-edit it:

- `index.html`, `*/index.html`, `404.html`, `gracias.html`, `sitemap.xml`, `docs/routes.json`
- the `SITE DEFAULTS` block in `lead-forward.php`

Change the source (`content.mjs`, `themes.mjs`, `zones.mjs`, `ideas.mjs`, `build-site.mjs`,
`assets/`), run `node build-site.mjs`, and commit the regenerated files together with the source.
Always rebuild before committing and leave `git status` clean.

## Commands

Run from the repo root. Needs Node 22 and PHP 8.1+ (PHP only for the last two rows).

| Task | Command | Runs |
| --- | --- | --- |
| Build the site | `npm run build` | `node build-site.mjs` |
| Verify (phase B5) | `npm run verify` | `node verify.mjs --phase B5` |
| Verify (final gate) | `npm run verify:final` | `node verify.mjs --final` |
| Local preview (port 4173, set `PORT` to change) | `npm run preview` | `node preview-server.mjs` |
| Smoke test the live site (GET only) | `npm run smoke` | `node deploy/smoke.mjs` |
| CSS audit | `npm run css-audit` | `node css-audit.mjs` |
| PHP syntax check | `npm run php:lint` | `php -l lead-forward.php` |
| PHP endpoint test | `npm run php:test` | `node docs/qa-tools/php-endpoint.mjs` |
| Stale-output guard: rebuild, fail if generated files differ from the commit | `npm run check:clean` | `node scripts/check-clean.mjs` |
| Build, final verify, PHP lint, PHP test, then the clean check | `npm run check` | the four steps above, then `check:clean` |

`package.json` only holds these scripts. It has no dependencies, so there is nothing to
`npm install` and no `node_modules`, and the server never uses it. To point the smoke test at
another origin, call it directly: `node deploy/smoke.mjs http://127.0.0.1:4173`.

The preview server is static only: it does not run PHP. The smoke test never submits a form.
Before pushing, run `npm run check`. The clean check runs last, so a normal local edit still gets
full build and test feedback first; `npm run check` fails until the regenerated output is
committed together with the source.

Optional pre-push hook (runs `npm run check` before every push): enable it once per clone with
`git config core.hooksPath .githooks`.

## Repo map

Source files (edit these):

- `content.mjs`: copy, prices (`PRICES`), WhatsApp number, packages, navigation
- `themes.mjs`, `zones.mjs`, `ideas.mjs`: theme, zone and guide data
- `build-site.mjs`: the generator and templates
- `assets/`: CSS, JS, self-hosted fonts and images
- `lead-forward.php`: the form endpoint (its `SITE DEFAULTS` block is generated)
- `.htaccess`, `robots.txt`: server rules and crawler rules
- `verify.mjs`, `css-audit.mjs`, `preview-server.mjs`: checks and local tools

Generated output (do not edit): `index.html`, `404.html`, `gracias.html`, `sitemap.xml`,
`docs/routes.json`, and one folder per route group with an `index.html` inside:
`bautismo/`, `bienvenida-de-bebe/`, `combos-y-precios/`, `como-funciona/`, `contacto/`,
`cumpleanos-infantil/`, `decoracion-con-globos/`, `ideas/`, `preguntas-frecuentes/`,
`primer-anito/`, `privacidad/`, `revelacion-de-genero/`, `servicios/`, `tematicas/`,
`terminos/`, `zonas/`.

Other folders and files:

- `docs/`: deploy notes, QA tools (`docs/qa-tools/`), route manifest, backlogs, session handoffs
- `deploy/`: smoke test, ZIP script, and `vendercrm-config.example.php` (the real config lives
  above `public_html` and is never committed)
- `plan/`: the original build plan, phase prompts and open questions (start at `plan/00-README.md`)
- `codex-input/`, `BRIEF.md`, `REVIEW.md`: early inputs and review notes
- `AGENTS.md`: instructions for the Codex worker process

`.htaccess` answers 403 for `plan/`, `docs/`, `deploy/`, `codex-input/`, dotfiles, `*.md`,
`*.mjs` and `*.ps1`, so none of these are public even though they are cloned to the host.
